RAG development services

Retrieval-augmented generation (RAG) lets a large language model answer from your documents, databases and internal knowledge instead of from memory. I design and build RAG systems that run in production: they cite their sources, respect who is allowed to see what, and are tested against real questions before anyone relies on them.

I've built RAG assistants for large Saudi enterprises, semantic matching used in government hiring, and open-source tooling that LangChain merged upstream. I work freelance or on contract, remote or on-site in Riyadh, with teams across Saudi Arabia, the GCC and MENA.

How a project runs

Step 1

Scope and test questions

We agree on the questions the system must answer and collect real examples with expected answers. That test set is written before any code, so every later change can be measured against it.

Step 2

Retrieval first

I build ingestion, chunking, embeddings and search, then measure retrieval on its own: does the right passage come back in the top results? Most weak RAG systems fail here, not in the LLM.

Step 3

Answers and guardrails

Prompts, citations and refusal rules on top of retrieval, plus access control so each user only gets answers from documents they're allowed to read. The model can be an API model or an open-weight model on your own servers.

Step 4

Deployment and monitoring

A FastAPI service in Docker on Kubernetes or your cloud, with logging, user feedback and dashboards. When documents, prompts or models change, the test set runs again before release.

Common questions

Can RAG run without sending data to an external API?

Yes. The whole stack, including the LLM, the embedding model and the vector database, can run on your own servers or in a cloud region inside Saudi Arabia.

On-premise LLM deployment

Does it work with Arabic documents?

Yes, with extra work on spelling normalization, dialects and mixed Arabic–English text. That work is covered on its own page.

Arabic LLMs and Arabic RAG

Should we fine-tune a model instead?

Sometimes, but RAG comes first in most projects: it keeps answers current and traceable without retraining. Fine-tuning with LoRA or QLoRA helps when you need a specific style, format or vocabulary, and the two work well together.
